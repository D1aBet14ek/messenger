# Выход в интернет — что и как

Здесь описано, как сделать так, чтобы мессенджером можно было пользоваться
**откуда угодно**, а не только на твоём компьютере.

---

## Главное, что нужно понять

Когда программа работает на твоём компьютере — она живёт, пока компьютер включён.
Чтобы работало круглосуточно и у всех, программу надо поставить на **хостинг** —
чужой компьютер, который никогда не выключается.

И тут есть важная ловушка: **у большинства бесплатных хостингов файлы стираются**
при перезапуске. Значит, если оставить базу данных файлом `chat.db`, однажды все
переписки могут пропасть. Чтобы диалоги сохранялись надёжно, базу лучше держать
**отдельно** — на «настоящей» базе данных PostgreSQL.

**Хорошая новость:** программа уже подготовлена к обоим случаям. Ничего
переписывать не нужно — достаточно задать несколько настроек на хостинге.

---

## Что уже готово в проекте

| Что | Зачем |
|-----|-------|
| Настройки из «переменных окружения» | Программа берёт адрес базы, ключ и порт снаружи |
| `DATABASE_URL` | Позволяет подключить базу PostgreSQL вместо файла |
| `SECRET_KEY` | «Ключ входа» задаётся снаружи (файл на хостинге не нужен) |
| `DATA_DIR` | Можно указать папку, которая не стирается (если хостинг её даёт) |
| `requirements.txt` | Список библиотек, включая «мотор» для хостинга |
| `Procfile` | Говорит хостингу, как запустить программу |
| `.gitignore` | Прячет личные файлы (`chat.db`, `secret_key.txt`) от чужих глаз |

Настройки, которые понимает программа:

| Настройка | Пример | Смысл |
|-----------|--------|-------|
| `SECRET_KEY` | `q7f...` | Длинная случайная строка для входа |
| `DATABASE_URL` | `postgresql://...` | Адрес базы данных (если не файл) |
| `DATA_DIR` | `/data` | Папка для файла базы (если решим оставить файл) |
| `DEBUG` | `0` | В интернете обязательно `0` (выключено) |
| `PORT` | `8080` | Хостинг обычно задаёт сам |

## Вариант A — надёжный, данные точно сохраняются

**Хостинг веб-сайта:** Render (бесплатно)
**База данных:** Neon или Supabase (бесплатно, PostgreSQL)

Кратко по шагам (подробно разберём вместе, когда выберешь этот путь):

1. Создать бесплатную базу на `neon.tech` → получить строку вида
   `postgresql://...` (это и есть `DATABASE_URL`).
2. Положить проект на GitHub (сайт для хранения кода).
3. На `render.com` → **New Web Service** → подключить репозиторий.
4. Указать команду запуска из `Procfile`.
5. Добавить настройки окружения: `SECRET_KEY` (случайная строка),
   `DATABASE_URL` (из шага 1), `DEBUG=0`.
6. Нажать Deploy. Получится адрес вида `https://имя.onrender.com`.

**Плюс:** данные не пропадают, адрес постоянный.
**Минус:** несколько регистраций, и на бесплатном тарифе сайт «засыпает» после
простоя (первый заход бывает медленным).

## Вариант B — самый простой, но с оговоркой

**Хостинг:** PythonAnywhere (бесплатно)

Там можно оставить файл `chat.db` — он сохраняется. Настройка делается через
их сайт (без GitHub). Нужно создать веб-приложение, указать, где лежит проект,
и в одном файле прописать пару строк.

**Плюс:** проще всего, данные сохраняются, ничего не платить.
**Минус:** у бесплатного аккаунта есть ограничения и он **истекает примерно через
месяц** (дальше — платно или заново). Также бесплатных ресурсов немного.

---

## Вариант C — платный, но самый беспробный

Заплатить небольшую сумму (примерно 5–7 долларов в месяц) на Render или
PythonAnywhere, чтобы получить постоянный сайт с «незасыпающей» базой и без
ограничений. Для настоящего мессенджера это самый спокойный вариант.

---

## Про безопасность (важно!)

Это учебный проект. Для настоящего интернета в нём пока нет:
- защиты от спама и от подбора паролей;
- защиты форм от хитрых подделок (так называемого CSRF);
- HTTPS-настроек (на хостинге он обычно даётся бесплатно автоматически).

Прежде чем пускать туда много людей, стоит добавить хотя бы первую из защит.
Когда дойдём до этого — я помогу.
