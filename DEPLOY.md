# Выход в интернет: пошаговая инструкция (Вариант A)

Здесь — что делать, шаг за шагом, чтобы мессенджер заработал по адресу в интернете.

Используем три бесплатных сервиса:

| Сервис | Зачем | Сайт |
|--------|-------|------|
| **GitHub** | Хранит код проекта | github.com |
| **Neon** | База данных (чтобы переписки не пропадали) | neon.tech |
| **Render** | Компьютер, который работает круглосуточно и показывает сайт | render.com |

---

## Что уже сделано за тебя

- ✅ Программа подготовлена: настройки берутся снаружи.
- ✅ Создан «чертёж» `render.yaml` — Render сам поймёт, как всё запускать.
- ✅ Создан список библиотек `requirements.txt`.
- ✅ Создан файл `Procfile` для хостинга.
- ✅ Заведён «склад кода» Git и сделан первый снимок (коммит).
- ✅ Личные файлы `chat.db` и `secret_key.txt` **не попадут** в интернет.

## Шаг 1. GitHub — заводим «склад кода»

1. Открой **github.com** и зарегистрируйся (или войди).
2. Нажми зелёную кнопку **New** (или «+» справа вверху → **New repository**).
3. Заполни:
   - **Repository name:** `messenger`
   - Вид: **Public**
   - Галочку «Add a README file» **НЕ ставь**.
4. Нажми **Create repository**.
5. Скопируй адрес репозитория вида `https://github.com/ТВОЙ_ЛОГИН/messenger.git`

## Шаг 2. Отправляем код на GitHub

Открой PowerShell в папке `messenger` и выполни по очереди (замени
`ТВОЙ_ЛОГИН` на свой логин GitHub):

```powershell
& "C:\Program Files\Git\cmd\git.exe" remote add origin https://github.com/ТВОЙ_ЛОГИН/messenger.git
& "C:\Program Files\Git\cmd\git.exe" push -u origin main
```

При первой отправке откроется окно входа в GitHub — войди в нём.
После этого код окажется на GitHub (обнови страницу репозитория — увидишь файлы).

## Шаг 3. Neon — заводим базу данных

1. Открой **neon.tech** и зарегистрируйся (удобно через кнопку «Sign in with GitHub»).
2. Нажми **Create project**. Имя любое. Нажми **Create**.
3. Появится адрес базы (Connection string). Он выглядит примерно так:

   ```
   postgresql://пользователь:пароль@что-то.neon.tech/база?sslmode=require
   ```

4. Скопируй его и сохрани — это наша настройка **DATABASE_URL**.

## Шаг 4. Render — запускаем сайт

1. Открой **render.com** и зарегистрируйся через **GitHub**.
2. Нажми **New +** → **Web Service** (или **Blueprint**, чтобы Render прочитал `render.yaml`).
3. Выбери репозиторий **messenger**.
4. Проверь настройки запуска:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app --bind 0.0.0.0:$PORT`
   (если используешь Blueprint — они уже заданы в `render.yaml`)
5. В разделе **Environment** добавь настройки:
   - `SECRET_KEY` — длинная случайная строка (можно нажать «Generate»)
   - `DATABASE_URL` — адрес из шага 3
   - `DEBUG` — значение `0`
6. Нажми **Create Web Service** и подожди пару минут, пока идёт сборка.

## Шаг 5. Проверяем

Render покажет адрес вида `https://messenger-xxxx.onrender.com`.
Открой его — увидишь вход в мессенджер. Зарегистрируйся и проверь переписку
со вторым окном (Инкогнито). Теперь всё работает из интернета!

---

## Если что-то пошло не так

- **Сайт долго открывается первый раз** — так устроен бесплатный тариф Render:
  сайт «засыпает» без посетителей. Просто подожди.
- **Ошибка при сборке** — открой на Render раздел «Logs» и посмотри красный текст.
  Покажи его мне — помогу.
- **Переписки не сохраняются** — значит, `DATABASE_URL` задан неверно. Проверь,
  что строка из Neon вставлена целиком.

## Другие варианты (на будущее)

- **PythonAnywhere** — проще всего (без GitHub), файл `chat.db` сохраняется,
  но бесплатный аккаунт истекает примерно через месяц.
- **Платный тариф** (5–7 долларов в месяц) — сайт не засыпает и работает быстрее.

## Про безопасность

Это учебный проект. В интернете стоит позже добавить защиту от спама и подбора
паролей. Обязательно держи `DEBUG=0` — иначе ошибки покажут внутренности всем.
