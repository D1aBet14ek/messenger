# Выход в интернет: свой сервер + Dokploy (Nixpacks)

Ты разворачиваешь мессенджер на **своём сервере через Dokploy**.
Это значит: данные живут на твоём сервере, никакие западные сервисы не нужны,
а работать будет круглосуточно и без твоего домашнего компьютера.

---

## Что уже готово в проекте

| Файл | Зачем |
|------|-------|
| `nixpacks.toml` | **Главное для Dokploy:** как собрать и запустить приложение |
| `.python-version` | Указывает версию Python (3.12) |
| `requirements.txt` | Список библиотек (Flask, SQLAlchemy, gunicorn и др.) |
| `Procfile` | Резервная команда запуска (на случай, если Nixpacks её спросит) |
| `app.py` | Программа. Читает настройки из окружения: `SECRET_KEY`, `DATABASE_URL`, `DATA_DIR`, `PORT`, `DEBUG` |

Менять код не нужно — только указать настройки в Dokploy.

---

## Что делать в Dokploy

### 1. Создать приложение

1. Войди в Dokploy → **Create Project** (создать проект), назови как угодно.
2. Внутри проекта → **Create Application**.
3. Тип сборки (**Build Type**): выбери **Nixpacks**.
4. Подключи свой GitHub-репозиторий `D1aBet14ek/messenger`
   (Dokploy попросит доступ к GitHub — разреши).
   Ветка: **main**.

### 2. Указать порт

В настройках приложения найди **Port / Container Port** и поставь:

```
8000
```

(Ровно этот же порт указан в `nixpacks.toml`. Если поставишь другой — поменяй
и там, или задай переменную `PORT`.)

### 3. Переменные окружения (Environment)

Добавь три настройки:

| Имя | Значение | Смысл |
|-----|----------|-------|
| `SECRET_KEY` | `a30baf34793cca34b4b960120957190a0c86f70b6bf6cd8d6aa8a5125e83b76a` | «Ключ входа», чтобы вход не сбрасывался |
| `DEBUG` | `0` | Выключить учебный режим (в интернете — обязательно) |
| `DATA_DIR` | `/data` | Папка, где лежит база данных |

### 4. Том для данных (Volumes) — самое важное!

Чтобы переписки **не пропадали** при обновлении приложения, базу нужно хранить
в отдельном «томе» (постоянном хранилище).

1. В настройках приложения найди **Volumes** (Тома) → **Add Volume**.
2. Заполни:
   - **Name / Volume Name:** `messenger-data`
   - **Mount Path:** `/data`
3. Сохрани.

Теперь база будет в `/data/chat.db` и останется на месте при любых обновлениях.

### 5. Запустить

Нажми **Deploy**. Dokploy соберёт приложение (2–4 минуты) и выдаст адрес.
Открой его — увидишь вход в мессенджер. Зарегистрируйся и проверь переписку
(второе окно — в режиме «Инкогнито»).

## Если хочешь «настоящую» базу данных (PostgreSQL)

Способ выше (SQLite + том) — самый простой и для небольшого мессенджера вполне
достаточный. Но если захочется надёжнее:

1. В Dokploy создай **PostgreSQL** (Dokploy умеет это одной кнопкой).
2. Скопируй его **внутренний** адрес подключения
   (вида `postgresql://пользователь:пароль@имя-базы:5432/база`).
3. В приложении добавь переменную окружения `DATABASE_URL` = этот адрес.
4. Перезапусти (**Deploy**).

Программа сама поймёт, что база — PostgreSQL, и создаст в ней таблицы.

## Как обновлять приложение потом

Всё просто: я (или ты) вносим изменения в код → отправляем на GitHub →
в Dokploy нажимаем **Deploy** (или включить авто-деплой при push).

## Про безопасность

Это учебный проект. Для открытого интернета позже стоит добавить:
- защиту форм (CSRF),
- ограничение частоты попыток входа (от подбора паролей),
- проверку настроек.

Обязательно держи `DEBUG=0`. Когда дойдём — я помогу добавить защиту.
