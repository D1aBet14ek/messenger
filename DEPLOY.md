# Выход в интернет: свой сервер + Dokploy (Nixpacks)

Ты разворачиваешь мессенджер на **своём сервере через Dokploy**.
Это значит: данные живут на твоём сервере, западные сервисы не нужны,
работает круглосуточно и без твоего домашнего компьютера.

---

## Что уже готово в проекте

| Файл | Зачем |
|------|-------|
| `nixpacks.toml` | **Главное для Dokploy:** как собрать и запустить приложение |
| `.python-version` | Версия Python (3.12) |
| `.gitattributes` | Правильные «переводы строк» для Linux-сервера |
| `requirements.txt` | Библиотеки (Flask, SQLAlchemy, gunicorn и др.) |
| `Procfile` | Резервная команда запуска |
| `app.py` | Читает настройки снаружи: `SECRET_KEY`, `DATABASE_URL`, `DATA_DIR`, `PORT`, `DEBUG` |

Команда запуска (из `nixpacks.toml`):

```
gunicorn app:app --bind 0.0.0.0:8000 --workers 2 --timeout 60
```

Порт — **8000**. Такой же нужно поставить у домена в Dokploy.

Все файлы уже отправлены на GitHub (`D1aBet14ek/messenger`).
**Код менять не нужно** — только указать настройки в Dokploy.

## Пошагово в Dokploy

В Dokploy у приложения есть вкладки: **General**, **Environment**, **Domains**,
**Advanced** и другие. Идём по ним.

### Шаг 0. Подготовка

- Dokploy уже установлен на твоём сервере, ты можешь войти в панель.
- Репозиторий `D1aBet14ek/messenger` на GitHub уже есть. ✅

### Шаг 1. Создать проект

1. В панели Dokploy нажми **Create Project**.
2. Название — например, `messenger`. Подтверди.

### Шаг 2. Создать приложение

1. Внутри проекта нажми **Create Service** → выбери **Application**.
2. Появится страница приложения с вкладками. Идём в **General**.

### Шаг 3. Вкладка General (источник кода и сборка)

Заполни так:

- **Name:** `messenger`
- **Provider:** `GitHub`
- Подключи GitHub: нажми кнопку подключения и разреши Dokploy доступ
  к своему репозиторию (ставится приложение Dokploy в GitHub — разреши ему
  доступ к `messenger`).
- **Repository:** `D1aBet14ek/messenger`
- **Branch:** `main`
- **Build Type:** `Nixpacks`  *(он обычно выбран по умолчанию)*

Нажми **Save**.

### Шаг 4. Вкладка Environment (настройки)

Добавь три переменные (по одной строке — «ключ = значение»):

| Имя | Значение |
|-----|----------|
| `SECRET_KEY` | `a30baf34793cca34b4b960120957190a0c86f70b6bf6cd8d6aa8a5125e83b76a` |
| `DEBUG` | `0` |
| `DATA_DIR` | `/data` |

Нажми **Save**.

### Шаг 5. Том для данных (Advanced → Volumes/Mounts)

Это нужно, чтобы переписки **не пропадали** при обновлениях.

1. Открой вкладку **Advanced** → раздел **Volumes/Mounts**.
2. Нажми добавить **Volume Mount**.
3. Заполни:
   - **Volume Name:** `messenger-data`
   - **Mount Path:** `/data`
4. Сохрани.

Теперь база данных живёт в `/data/chat.db` и остаётся на месте при пересборках.

### Шаг 6. Домен (вкладка Domains)

Чтобы открывать мессенджер по ссылке:

1. Открой вкладку **Domains** → **Add Domain**.
2. Можно:
   - ввести **свой домен** (если есть), или
   - нажать создание **бесплатного домена** (Dokploy умеет генерировать через traefik.me).
3. В поле **Port** укажи **`8000`** — ровно тот порт, на котором слушает gunicorn.
4. HTTPS (SSL/Let's Encrypt) — желательно включить, если есть свой домен.
5. Сохрани.

### Шаг 7. Запустить

Нажми кнопку **Deploy** (вверху страницы приложения).
Dokploy соберёт образ (2–4 минуты). Следи за прогрессом во вкладке
**Deployments** или смотри **Logs**.

Когда сборка завершится — открой свой домен. Увидишь вход в мессенджер.

### Шаг 8. Проверка

1. Зарегистрируй первого человека.
2. Открой второе окно браузера **в режиме «Инкогнито»** и зарегистрируй второго.
3. Напиши сообщение с одной стороны — второе окно подхватит его само
   примерно через 3 секунды. ✅

## Если что-то не так

- **Ошибка 502 «Bad Gateway»** — приложение не отвечает на нужном порту.
  Проверь две вещи:
  1. В **Domains** порт стоит **8000** (и там же включён HTTPS).
  2. Не задана переменная `PORT` в Environment (не нужна).
  Затем нажми **Redeploy**.
- **Приложение падает при старте** — открой вкладку **Logs**, там будет текст
  ошибки. Пришли его мне.
- **Сборка падает (красный текст в Deployments)** — тоже пришли текст, разберёмся.
- **Переписки пропадают после обновления** — не сделан том `/data`
  или не задан `DATA_DIR=/data`.

## Если хочешь «настоящую» базу данных (PostgreSQL)

Способ выше (SQLite + том `/data`) для небольшого мессенджера вполне хорош.
Но можно сделать ещё надёжнее:

1. В Dokploy: **Create Service** → **Database** → **PostgreSQL**.
2. Скопируй его **внутренний** адрес подключения
   (вида `postgresql://пользователь:пароль@имя-базы:5432/база`).
3. В приложении (вкладка **Environment**) добавь переменную `DATABASE_URL` = этот адрес.
4. **Deploy**. Программа сама создаст таблицы в PostgreSQL.
